Efficient Search for Arbitrary p/q Blocking Flows ​

Source page ID: Y42aDe4xcQvaf0pwbojSMQ | Open in Tencent Docs

For the latest implementation and algorithmic details, refer to GitHub: hongshan-academy/TopoConstructor!

This algorithm mainly builds on @Orirock's three-way splitting/merging construction and @madSUN's 1/n blocking-flow algorithm. Its correctness rests on conclusions from existing work.

Operators ​

The idea is to reduce a target p/q into several unit fractions 1/n and fractions in [1/3,1/2], then use dynamic programming (DP) to search for better constructions.

Operator Principles ​

Unit Fractions ​

See Some Research and Searches on 1/n Blocking FlowsSome Research and Searches on 1/n Blocking Flows, and unit.py.

For U(n), first write n=2ar, where r is odd. Multiply several U(2) constructions through full-edge replacement for the 2a part. For the odd part, search two feedback permutations whose recurrence denominator is exactly r. Enumerate permutation pairs directly at small search layers; larger layers can use MILP.

Interval Fractions ​

See Blocking-Flow Research Centered on Idealized-System Rate LimitersBlocking-Flow Research Centered on Idealized-System Rate Limiters, JNK's introductory article on blocking flows, and interval.py.

For I(p,q), split the flow into binary or ternary segments, then merge them into three port groups. By default, prefer a target-directed mixed-radix chain. If no suitable chain exists, use a compact binary construction subdividing only boundary segments. With extra optimization enabled, perform bounded search within the given range and select the scheme with fewer elements.

DP Search ​

  • A DP state consists of the current fraction and remaining search depth.

  • Each state compares candidates including the old reduction, binary remainders, Full(1) subtraction, scaling, additive and subtractive decompositions.

  • Additive/subtractive splits retain only child denominators no greater than the current target denominator, preferentially trying combinations obtained from prime-power blocks of that denominator.

  • At the depth or state-count limit, fall back to the old reduction, always retained as a fallback.

  • Unsearched U(n) initially receives a lower-bound cost estimate. If it appears in the winning plan, compute its actual topology and rerun planning until all costs are exact.

Graph Generation and Verification ​

Only after the symbolic tree is fixed does the program recursively generate the graph:

All flows are calculated with exact fractions.

Finally, the program checks node types and degrees, conservation, fixed-edge rates, edge-state propagation, local maximum rules and equal flow on parallel edges. It then writes these as linear equations for all edge flows and calculates rank using exact Gaussian elimination. If rank equals edge count, the constraints uniquely determine the flow solution.

Although the outer DP has depth and state-count bounds, internal Unit/Interval searches have no polynomial-time guarantee in input bit length log⁡q. Even if we have proved k=Θ(log⁡q), Unit enumeration may still reach qΘ(log⁡log⁡q).
