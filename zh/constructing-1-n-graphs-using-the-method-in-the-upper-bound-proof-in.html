基于△中上界的证明中涉及的方法的 1/n 图构造 ​

源页面 ID：bv2zQeultUImM3nXJQE36y ｜ 在腾讯文档中打开

构造原理 ​

考虑一个 1/3k 阻塞流

在一般流中，Ak 和 Bk 的上界是 3k，而在这个阻塞流 1/3k 中，Ak 和 Bk 达到上界当且仅当所有的分流器 Si 的两条出边都连接 Ci，每个 Si 的两条出边全部连接 Ci 的结构引入了一次乘以 3 的乘法

**但这个乘法实际上来自三个相同的 **Ak**相加，**由于 Bk−1=Ak−1 在该流中恒成立，我们有

Ak=Ak−1+min{Bk−1,Ak−1}+min{Bk−1,Ak−1}=3Ak−1

如果引入一对新的 →Cn→Sn→，然后删除一条 Sn→Cn 和一条 Si→Ci 并新连接 Sn→Ci 和 Si→Cn，则根据算法

An=An−1+min{Bi,An−1}+min{Bn−1,An−1}=An−1+3i+3n−1

我们可以继续修改另一条边并得到

An=An−1+min{Bi,An−1}+min{Bj,An−1}=An−1+3i+3j

如果恰好 i=j，则我们有 An=An−1+2⋅3i，对应三进制中的 2

除了最高位的 2 的情况需要一次单独修改重连一条边以外（+3r+3a），其他的一次修改重连一条边或两条边，正好可以表达三进制；为了方便，我们让其两两配对进行连接（+3a+3b），对于 di=2 的情况，记两次相同的 3i 即可

构造算法 ​

  1. 写出三进制表示 (d0d1⋯dr)3，长度 r+1，最高位 dr

  2. 画出长度为 r 的主链

In→C0→⋯→Cr−1→Sr−1→⋯→S0→Out

其中每个分流器 Si 都有两条指向 Ci 的回流

  1. 如果 dr=2：在主链正中央增加 →Cr→Sr→（其中 Sr 的两条回流都指向 Cr），然后

    1. 选一个满足 di≠0 的 i（例如最大的那个 i）

    2. 断开一根 Si→Ci

    3. 连接 Si→Cr

    4. 连接 Sr→Ci

    5. 把 di 减去 1

  2. 把剩下的 di（i=0,…,r−1）中所有 di≠0 的 i 写成一串数（i 写 di 次），从小到大排好，每两个合成一对。对每一对 (i,j)：在主链正中央新增一对 →Ck+1→Sk+1→（其中 Sk+1 的两条回流都指向 Ck+1），然后

    1. 断开一根 Si→Ci

    2. 连接 Si→Ck+1

    3. 断开一根 Sj→Cj

    4. 连接 Sj→Ck+1

    5. 断开 Sk+1 的两条 Sk+1→Ck+1

    6. 连接 Sk+1→Ci

    7. 连接 Sk+1→Cj

代码 ​

python
def base3(q):
    d = []
    while q > 0:
        d.append(q % 3); q //= 3
    return d

def build_edges(q):
	# step 1
    d = base3(q)
    r = len(d) - 1
    
    # step 2
    # (i, j) := S_i -> C_j
    E = []
    for i in range(r):
        E += [(i, i), (i, i)]
    k = r
    
    # step 3
    if d[r] == 2:
        i = max(t for t in range(r) if d[t] != 0)
        n = k; k += 1
        E.remove((i, i))
        E += [(i, n), (n, i), (n, n)]
        d[i] -= 1
        
    # step 4
    seq = [i for i in range(r) for _ in range(d[i])]
    for t in range(0, len(seq), 2):
        i, j = seq[t], seq[t + 1]
        n = k; k += 1
        E.remove((i, i)); E.append((i, n))
        E.remove((j, j)); E.append((j, n))
        E += [(n, i), (n, j)]
        
    return k, E

算法扩展 ​

由于该算法基于 1/n 阻塞流的主链与回流结构的数学性质，扩展到 2, 3 混合进制应当是相当容易的。

但我太困了明天再说。

实验表明，2, 3 混合进制总是不差于 2 或 3 进制。这和其中涉及的逐 digit 和有关系。

该算法不能搜到一些已知最优解，这是因为这类解往往涉及更一般的加法结构，无法单纯用进制表达。如要搜索，难以避免 (k!)^2 级的算法。
